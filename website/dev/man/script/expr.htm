Introduction

An expression combines literals, names, and operators to produce a value. Expressions do not create or modify entities; they only compute results. All operators follow the usual precedence rules, and mixed-type expressions use the promotion rules described below.

Expression Evaluation Model

Expressions are evaluated from left to right, subject to operator precedence. Each operator defines how its operands are combined, including any type promotion needed to produce a valid result. Evaluation always produces a single value or an error.

  • Left to right - Expressions are evaluated from left to right, subject to operator precedence.
  • Operator precedence - Operators with higher precedence are evaluated before operators with lower precedence. The precedence table appears later in this page.
  • Type promotion - Mixed‑type expressions promote values as needed (for example, numbers to Fields, Fields to ranges). Full rules are described in the Promotion section.
  • Special Field values - +infinity, -infinity, and ? behave like IEEE‑754 float infinities and NaN. They propagate through expressions according to their semantics.
  • Errors - Any error produced by an operator stops evaluation and becomes the result of the expression
  • Side effects - Expressions do not create or modify entities. However, functions invoked within an expression may access or modify global variables, depending on how the function is defined.

Type Promotion and Demotion

Expressions involving ranges and rlists use a unified internal representation. All set operators (!, |, &&, \\, ^^) operate on rlists, regardless of whether the operands are numbers, fields, ranges, or rlists. Promotion and demotion happen automatically and are usually invisible.

Promotion

  • Numbers → Fields - Numbers are promoted to Fields whenever an operator requires Field behaviour.
  • Fields → Ranges - Fields are promoted to ranges with start and end equal to the field value.
  • Ranges → Rlists - Ranges are promoted to rlists with a single range element.
  • All set operations work internally on rlists.

Demotion

After an operation completes, the result is demoted to the simplest type possible.

  • Rlists → Ranges - Rlists are demoted to a range if it consists of a single range.
  • Ranges → Fields - Ranges are demoted to a field if the start and end are equal.
  • Fields → Numbers - No further demotion occurs unless an operator requires a numeric value.

Numbers vs Fields

Printed output does not distinguish numbers from fields. Both appear simply as integers. The only way to determine the underlying type is:

@type(value)

which returns the type name as a string.

Unary operators apply to numbers, fields, ranges, and rlists.

Unary Minus '-'

Unary minus has normal meaning of negation.

Negation of a range negates both limits. It reflects a range about zero, re-normalising it to ascending order which reverses its endpoints. Applying it twice returns the original range.

-(a..b) = -b..-a

Negation of an rlist negates all the ranges, but retains the well orderliness.

-(a..b | c..d) = -d..-c | -b..-a

Binary Plus '+' and Minus '-'

Normal addition or subtraction is applied when both sides of an expression are numeric values. A numeric value can be added or subtracted from range or rlist. But ranges and rlists cannot be added or subtracted from each other and will result in an error.

a + (b..c) = a + b..a + c
(a | b..c) + d = a + d | b + d..c + d

Subtraction is carried out by adding the negated right hand side.

a - b = a + -b
a - (c..d) = a + (-d..-c) = a - d..a - c

Multiplication, Division and Modulo

Currently, these operators can only be used with numerical types, float, number and field. Use with ranges and rlists will result in an error.

If one operand is a float the other operand will be promoted to float before the operation.

If one operand is a field the other operand will be converted to a field if possible before the operation. An error will result if the conversion is not possible.

Multiplication

The multiplication operator '*' has the normal meaning of multiplication.

Float multiplication follows the IEEE-754 standard for floating point arithmetic.

  • Multiplication of any number with +infinity (except ? and -infinity) results in +infinity.
  • Multiplication of any number with -infinity (except ? and +infinity) results in -infinity.
  • Multiplication of -infinity and +infinity values is ?.

Division and Modulo

Glich has three distinct division operators, floating point division '/.', integer division '\' and natural division '/' which depends on the types of the operands.

It has an integer only modulo operator '%' and a combined integer division and modulo operator '/%' which returns a quotient and remainder object.

Integer division and modulo operators are based on Euclidean integer division. This means that the quotient is always rounded down to the next integer (the floor) and the remainder is always positive.

Floating Point Division

Floating point division '/.' always returns a floating point result. It follows the IEEE-754 standard for floating point arithmetic.

The natural division operator '/' follows the same rule if one or both operands are a float. If only one operand is a float, the other operand will be promoted before the operation.

Integer Division

Integer division '\' always returns an integer result. It follows the Euclidean division rules described above.

If one or both operands are fields, the result will be a field. If only one operand is a field, the other operand will be promoted before the operation. If promotion is not possible the result will be '?' unknown.

Division with field operands follows the following rules:

  • Division of any number by 0, ?, -infinity or +infinity results in '?'.
  • Dividing +infinity by any number except 0, ? or +/-infinity results in +infinity.
  • Dividing -infinity by any number except 0, ? or +/-infinity results in -infinity.

Integer Modulo

The modulo '%' operator is used for integer modulo. It computes the remainder of the integer division of its operands and follows the Euclidean division rules described above.

  • The right hand side (divisor) must be a non-zero, finite integer. Anything else results in an error.
  • If left hand side (dividend) is +/-infinity, the result is 0.
  • If left hand side (dividend) is ? the result is an error.

If the result of the modulo operation is not an error, it will return a finite, non-negative integer less than the divisor.

Note, these rules have been set to ensure the following is always true:
If q = a \ b and r = a % b then a = b * q + r and r is always positive.

Combined Integer Division and Modulo

The combined integer division and modulo operator '/%' (divmod) returns a quotient and remainder object. It follows the same rules as the integer division and modulo operators. If either the division or modulo operation would result in an error, then the combined operation will also result in an error.

a /% b = {: a \ b, a % b}

Integer Range and Set Operations

Integer set operations work on fields, ranges and rlists, collectively known as set types. All numeric types (numbers, Fields, ranges) are automatically promoted to rlists when used with set operators. If a number can not be promoted to a field (due to overflow), an error will result. After the operation completes, the result is demoted to the simplest set type possible. Set operators always use inclusive integer semantics and operate on canonical (well ordered) rlists internally.

Range Operator '..'

The range operator constructs the smallest inclusive range that contains both operands.

a .. b = @min(a, b)..@max(a, b)
  • Operands may be fields or ranges.
  • Numbers are promoted to fields automatically.
  • ? is an error.
  • -infinity and +infinity are allowed.
  • The result is always a non‑empty range (start <= end).
  • Multiple '..' operators collapse to the smallest range containing all operands.

Note that when printing a range, the start and end fields are separated by the range operator.

Set Operators

The set operators operate on set_types (fields, ranges, rlists). Number types will be promoted to fields if possible. The output is always a demoted set_type.

The canonical form of a set is a well ordered rlist. That is, a list of non-overlapping and non-adjacent ranges in ascending order.

A unary operator that constructs the set of all elements not in the operand set.

Comparison Operators

The comparison operators must have operands of the same type, after allowing for type promotion. The output is always a boolean type.

Any types, other than error types, can be compared for equality or non-equality.

Comparison operators that compare magnitude can only be used with numeric or string types. Use with any other type results in an error.

Subscript operators

The subscript operators allow access to to the various parts of the more complex value types.

Index operator

Used in the form Value[ Index ], the square brackets are used to enclose an index into left hand value.

If the value is a rlist type and the index a number type, then the result is the range pointed to by the (zero based) index.

If the value is an object type and the index a number type, then the result is the member value. If the index is a name or string value then this is matched with an objects member variable name and the result is the corresponding value.

ExampleResult
(8..16|20..50|75..99)[1]20..50
{complex 10, 25}[1]25
{complex 10, 25}[real]10

Function Operator

OperatorNameUse TypeResult Type
@Unary function.qualifier( arguments )@ function_namevalue
@Object function.qualifier( arguments )object_type @ object_function_namevalue

The unitary function operator introduces either a built-in or a user defined function.

User defined functions first have to be defined using the function statement. They can then be called in an expression using the at '@' operator.

When defining a function, it has an additional local variable: result. When the function is used in an expression, its value is that of the 'result' variable.

ExampleResult
function power(number, power) { result = 1; do { while power > 0; result *= number; power -= 1; }; };
4 * @power(2,4) + 1074

The object function operator is a function that uses the object on the left hand as input. The function may be a general object function that acts on all object types or a function defined as part of a named object.

ExampleResult
object pair { values first second; function sum { result = first + second; }; };
{pair 3, 4} @ sum7
